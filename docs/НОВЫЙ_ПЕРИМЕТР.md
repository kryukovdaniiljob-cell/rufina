# Как развернуть инструмент на другой периметр

Инструмент не привязан к конкретным товарным направлениям. Всё, что
определяет «чьи это направления», лежит в двух файлах настроек. Код
менять не нужно.

Ниже — порядок для коллеги, у которой такая же сквозная аналитика,
но другие направления.

---

## Что нужно

1. Установленный [Python](https://www.python.org/downloads/) — при
   установке обязательно галочка **«Add Python to PATH»**.
2. Копия этой папки целиком.
3. Свои выгрузки: сквозная аналитика — обязательно, остальные желательно.

Библиотеки поставятся сами при первом запуске.

---

## Шаг 1. Своя копия папки

Скопируйте папку `РТГ-Аналитика` целиком и переименуйте — например
`РТГ-Аналитика-Иванова`. Внутри новой копии очистите:

```
1_ВХОД/       — удалить всё, кроме .gitkeep
2_АРХИВ/      — удалить папки с датами
3_ОТЧЁТЫ/     — удалить папки с датами
база/         — удалить история_стока.parquet и снимки.json
```

Это чужие данные и чужая история: если их оставить, сравнение
«день ко дню» будет считать от не своих цифр.

---

## Шаг 2. Задать периметр

Периметр — это набор сочетаний **направление → группа 1 → группа 2**,
которые считаются «своими». Задаётся одним из двух способов.

### Способ А: по фамилии менеджера (проще)

В файле `config/settings.yaml`:

```yaml
периметр:
  категорийный_менеджер: "Фамилия И.О."
  использовать_scope_json: false
```

Имя должно совпадать **посимвольно** с тем, как оно записано на листе
«Матрицы» файла сквозной аналитики, в блоке
«Матрица_категорийных_менеджеров». Инструмент сам вытащит оттуда все
направления этого менеджера.

Если имя не совпадёт, расчёт остановится и скажет об этом — молча
посчитать чужой периметр он не может.

### Способ Б: списком (надёжнее)

Если в матрице менеджеров нет или она устарела, периметр задаётся
файлом `config/scope.json`:

```json
[
 {"gp": "Группы Комфорт",
  "td": "ИСРМ",
  "g1": "ИСРМ: Отопление и водоснабжение",
  "g2": "Водоподготовка"}
]
```

Поля берутся из листа «Каталог» сквозной аналитики:

| Поле | Колонка каталога |
|---|---|
| `gp` | Группа планирования |
| `td` | Товарное направление |
| `g1` | Группа 1 |
| `g2` | Группа 2 |

Одна строка на каждое сочетание. Названия должны совпадать посимвольно,
включая двоеточия и пробелы.

В `settings.yaml` при этом:

```yaml
периметр:
  категорийный_менеджер: null
  использовать_scope_json: true
```

---

## Шаг 3. Проверить ставки

В `config/settings.yaml`:

```yaml
экономика:
  ставка_хранения: 0.346      # доля от стоимости запаса в год
  ставка_капитала: 0.220
```

Это ставки из юнит-экономики РТГ. Если у коллеги другое подразделение
со своей экономикой склада — поправить. От них зависит порог GMROI и
вся логика «отрабатывает / не отрабатывает хранение».

Остальные пороги (`план_задач`, `запас`) можно оставить как есть —
они не привязаны к направлениям.

---

## Шаг 4. Первый запуск

1. Положить выгрузки в `1_ВХОД`.
2. Двойной клик по `ЗАПУСТИТЬ.bat`.
3. Проверить журнал:

```
Периметр из config/scope.json: N сочетаний
SKU в периметре: NNNN из NNNNN
Офисы из выгрузки: N — ...
Самопроверка: 11 проверок пройдено, расхождений нет
```

**Если «SKU в периметре» подозрительно мало или ноль** — периметр задан
неверно: названия групп не совпали посимвольно. Расчёт остановится с
понятным сообщением.

**Если «Самопроверка» нашла расхождения** — цифрам верить нельзя,
покажите журнал.

---

## Что менять НЕ нужно

* **Офисы и филиалы** — берутся из выгрузки автоматически. Если у коллеги
  другие города, они подхватятся сами. Настройка `периметр.офисы` нужна
  только чтобы СУЗИТЬ список.
* **Названия складов, типы складов** — определяются по содержимому имени
  («Основной склад», «Витрина», «Cash&Carry», «РРЦ»).
* **Месяцы, период расчёта** — берутся из данных: от 1 января до
  последней даты продажи в файле.
* **Структура отчётов** — одинакова для любого периметра.

---

## Что делать с GitHub

Публиковать отчёты в общий репозиторий не обязательно — инструмент
полностью работает локально, `ЗАПУСТИТЬ.bat` интернета не требует.

Если коллеге нужен онлайн-дашборд, ей нужен **свой** репозиторий: иначе
её отчёты лягут поверх ваших. Порядок тот же, что был у вас, только
`git remote` указывает на её репозиторий.

**Исходные выгрузки в GitHub не отправляются никогда** — в них ФИО
менеджеров с их личными продажами. `ОБНОВИТЬ САЙТ.bat` отправляет только
папки `3_ОТЧЁТЫ`, `docs` и `база`.

---

## Если что-то не сходится

Первым делом — лист **«00c.Самопроверка»** в Excel. Одиннадцать сверок:
сходятся ли числа между уровнями дерева, совпадает ли итог на титуле с
суммой по позициям. Все строки «ок» — расчёт согласован.

Дальше — лист **«00b.Логика»**: там человеческим языком описано, как
считается каждый показатель и откуда берётся каждый порог.
